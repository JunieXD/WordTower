# 请求频率与网络恢复

WordTower 允许持续正常刷题，没有每日题数上限。频率保护只约束单个登录用户的新任务，多设备共用额度；查看资料、历史和排行榜不消耗额度。

## 一次操作，只处理一次

客户端为一次操作生成 `Idempotency-Key`，自动重试和失败后的手动重试沿用同一标识。相同操作正在发送时，前端复用同一个 Promise。后端按用户缓存最近 512 次成功响应，最长保留 24 小时；正在处理的重复请求返回 `425 REQUEST_IN_PROGRESS`，不会创建第二个任务。

翻译批改按内容去重；普通作答按关卡和题目去重；每日挑战作答按挑战日和题目去重。相同操作标识搭配不同内容返回 `409`。结果缓存按用户隔离。客户端离开战斗页会取消过时的等待与请求，登出会清除客户端重试标识。

客户端最多自动重试一次网络错误、一次 `429`；`425` 在总计约一分钟的重试窗口内确认已有结果。所有重试沿用原始内容及标识。超过窗口后提供手动重试，不无限请求。限流提示使用温和倒计时，输入和当前题目在失败时保留。

## 额度如何计算

| 操作 | 额度 |
| --- | --- |
| 返回已有题目、已有响应、本地翻译预检 | 0 |
| 普通闯塔新生成一道题 | 1 |
| 一次大模型翻译批改 | 1 |
| 每日挑战新开局/缺题恢复 | 1 |
| 每日挑战一次新作答推进（含批改及紧接的下一题） | 1 |
| 一道后台预生成题目 | 1；没有富余容量就跳过 |

这里的额度单位是有界的业务任务，不是单个模型 HTTP 请求。一道题的生成、审核和有限重试仍由现有生成流程约束。普通闯塔优先生成当前需要的一题，取消一次启动五道题的投机批量；后台最多前瞻一道，并保留两个令牌供交互操作使用；所有后台模型请求合计最多占用一个全局并发槽位。每日共享预热不由概览查询触发。

## 配置

写入后端或生产部署目录的 `.env`，重新创建后端容器后生效：

```dotenv
TRAFFIC_BURST=8
TRAFFIC_REFILL_SECONDS=3
TRAFFIC_COOLDOWN_SECONDS=15
```

默认允许储存 8 个令牌，每 3 秒恢复 1 个。缺少额度时，后端只在等待不超过 2 秒的情况下短暂等待；否则返回 `429` 和 `Retry-After`。每位用户同时最多一个交互任务持有处理锁，不为涌入请求建立无限任务队列。

只有连续三个 10 秒时间段内，每段都有至少 3 个不同的新操作超额，才触发 15 秒冷却。相同操作的重试只观察一次；单次断网重连形成的大突发、后台预生成不足均不触发冷却。冷却期间不会延长截止时间，到期自然恢复，不升级为封禁。

## 运行边界

- Redis Lua 使用服务端时间原子扣减；处理锁定期续租，缓存与额度状态自动过期。
- Redis 不可用时返回可重试的 `503`，不绕过保护调用大模型。
- ECNU 的全局三并发限制继续生效；生产保持一个 Uvicorn worker。
- 这是单账号频率保护，不是多账号反滥用系统，也不是学校账号的总配额管理。
- 响应重放缓存不是数据库事务日志。进程崩溃、缓存丢失等极端故障仍需依赖业务记录恢复，不能承诺跨故障的严格 exactly-once。

后端测试使用 fakeredis 的真实 Lua 执行支持验证突发、续补、并发、用户隔离、冷却及重试；不调用真实大模型。
